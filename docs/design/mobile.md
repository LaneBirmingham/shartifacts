# Mobile workspace and fullscreen

At widths up to 900 CSS pixels, **Library** opens a drawer with search,
the **Artifacts · Apps** switch, the folding **Filters** (tag chips, type, time
and contents), and the menu for a new artifact, media, agent connection and
sign-in. Close it with **Close library**, the backdrop, or Escape (Escape in a
search box with text clears it first). Selecting an artifact closes it; a tag
in the details panel opens it, filtered to that tag.
The drawer keeps keyboard focus inside and restores focus when closed.

An open artifact fills the workspace beneath the toolbar at every width (52
pixels up to 900, 64 above). The toolbar holds the title, the version and view
switches, **Comment** (comment mode), **Comments**, **Share**, **ⓘ** (details)
and **Fullscreen**. Below 1280 pixels the views and comment buttons are icons,
their words kept as names for screen readers, and **Comments** shows its count
as a number. Up to 900 pixels the version and view switches move to the top of
the details panel, and picking a view there closes the panel; up to 640 the
library and Share buttons are icons too, and up to 480 the title gives way to
the buttons.

**ⓘ** and **Comments** open one side panel (full width on phones), on its
**About** or **Comments** tab, that Escape or × closes; it closes again when
another artifact opens. From 1280 pixels the panel sits beside the artifact
rather than over it, so its pins stay in view; on a phone, showing a thread's
spot in the artifact closes the panel first. **Edit title, description & tags**
closes it and starts editing. The
comment composer opens beside what was picked and stays inside the screen. Large screens retain the
permanent library, with the viewer chip at its foot.

**Fullscreen** displays the artifact alone with an **Exit fullscreen** button.
It uses browser fullscreen when available and otherwise fills the page viewport,
including on ordinary LAN HTTP. Escape also exits the viewport fallback when
focus is in the workspace. Native browser fullscreen supports the browser's own
exit mechanism. Returning preserves the selected view, version, and live frame.
The floating exit button intentionally overlaps a small corner of the artifact.

All artifact kinds support this presentation; slide decks also take F themselves. Video controls can enter native
media fullscreen independently. The iframe delegates fullscreen, clipboard-write, camera, microphone, geolocation and display-capture (each still prompts);
its sandbox flags match the response CSP's (`allow-scripts allow-forms
allow-modals allow-downloads allow-popups allow-popups-to-escape-sandbox
allow-pointer-lock`), its origin remains opaque, and fullscreen does not change
the CSP. Network, storage, parent access, forms, and nested
frames retain their existing restrictions.

## Measured verification

Local Chrome browser tests, 2026-10-16. Visible height is the iframe rectangle
intersected with the viewport, measured at the initial scroll position.

| Viewport | Preview top before / after | Visible preview height before / after | Viewport share before / after | Page scroll width before / after |
| --- | --- | --- | --- | --- |
| 697 × 837 | 343.88 / 52 px | 471.19 / 784 px | 56.3% / 93.7% | 697 / 697 px |
| 390 × 844 | 601.59 / 52 px | 242.41 / 791 px | 28.7% / 93.7% | 390 / 390 px |

The baseline confirmed the breakpoint gap and excessive chrome. The video
fixture did **not** reproduce horizontal overflow before the change; the reported
812-pixel overflow was not universal. Afterward, automated assertions also cover
320, 430, 640, 812, 900, 901, 1024, and 1440-pixel widths, a 200-character title,
expanded mobile details, and short-screen editing.

`npm run test:browser` builds and runs an isolated server against temporary data.
It verifies the html, react, markdown, svg, mermaid and code kinds in fullscreen at phone, fold, and desktop widths;
native video fullscreen by clicking the browser's control and checking the actual
fullscreen element; absent/denied Fullscreen API fallback; external fullscreen
exit; view restoration; pinned historical links; keyboard save; drawer dismissal;
and existing draft, conflict, sandbox, media, and persistence contracts.
Screenshots are written under `test-results/`, including `mobile-before-*.png`
from the baseline run, `mobile-after-*.png`, `fullscreen-*.png`, and
`native-video-fullscreen.png`. Baseline screenshots are local evidence and are
not regenerated by the updated gate.

Required checks:

```sh
go test ./...
go build ./...
go vet ./...
npm run test:browser
git diff --check
```

These are local browser and build results, not physical Galaxy Fold testing or
deployment verification. No deployment is part of this change.
